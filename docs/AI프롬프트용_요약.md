## 프로젝트 개요

**주제**: 동네 진단 — 자취방 구하기 전 "우리 동네 성적표" 서비스. 주소 하나만 입력하면 해당 지역의 안전·생활편의·교통 접근성을 종합 점수화해서 보여주는 웹 리포트 서비스.

**문제의식**: 직방·다방 등 부동산 앱은 시세·매물 정보만 제공. 안전(공공 안전 포털)·생활편의·교통 정보는 각기 다른 서비스에 흩어져 있어 "살아보기 전엔 알 수 없다"는 문제가 있음. 기존 서비스는 매물 선택 이후의 "사후 확인" 수준 정보만 제공하며, 여러 지역을 종합 점수로 비교하는 "사전 진단" 기능은 부재.

**차별점**: 기존 부동산 앱(거래 정보, 매물 선택 이후) vs 동네 진단(공공데이터 기반 정주 여건, 지역 선택 이전 사전 진단)

**플랫폼**: 웹 (앱이 아닌 이유 — 위치기반 네이티브 기능이 필수가 아니고, 배포·테스트가 간단해 학기 일정에 유리. 필요 시 PWA 확장 가능)

## 활용 데이터 및 출처

1차 버전은 **3개 지표**로 스코프 한정 (생활소음 지표는 구·군 단위 공개 데이터 부재로 1차 범위에서 제외)

| 지표 | 데이터셋 | 출처 | 형태 |
|---|---|---|---|
| 안전 | 경찰서별 5대 범죄 발생 현황 | 공공데이터포털(data.go.kr) | CSV |
| 생활편의 | 소상공인시장진흥공단_상가업소정보 | 공공데이터포털(data.go.kr) | CSV/API |
| 생활편의(보조) | 병원정보서비스 | HIRA, data.go.kr 등록 | API |
| 교통 접근성 | 버스정류장·지하철역 위치 | 부산 Big-데이터웨이브, TAGO | CSV/API |
| 주소→좌표 변환 | 지오코딩 | 카카오맵 API | API |

> 안전 지표는 GIS 공간분석이 필요한 생활안전지도(safemap.go.kr) WMS 데이터 대신, 구 단위 집계가 바로 가능한 경찰서별 범죄 통계 CSV 채택 (구현 난이도 낮춤).

## 기술 스택

| 영역 | 기술 |
|---|---|
| 프론트엔드 | React (Vite) + Tailwind CSS |
| 시각화/지도 | Recharts, 카카오맵 JavaScript SDK |
| 백엔드 | Python + FastAPI (+ Uvicorn, SQLAlchemy, requests, python-dotenv, CORS 설정) |
| 데이터베이스 | PostgreSQL (Supabase 클라우드) |
| 데이터 전처리 | Python + pandas |
| 배포 | 프론트: Vercel/Netlify, 백엔드: Render/Railway |
| 협업 도구 | GitHub, Notion |

**데이터 파이프라인**: 공공데이터(CSV/API) → Python/pandas 전처리·점수화 → PostgreSQL(Supabase) 적재 → FastAPI REST API → React 프론트엔드 조회·시각화

---

## 확정된 설계 결정사항 (중요)

- **점수화 방식**: 각 지표(범죄율, 편의시설 밀도, 교통 접근성)를 0~100점으로 정규화 후 가중합으로 최종 점수 산출
- **경찰서 관할구역 ↔ 행정동 매핑**: 경계가 정확히 일치하지 않아 팀이 직접 매핑 기준표를 작성해서 사용
- **정규화 기준 통일 필요**: 여러 지표(범죄·편의시설·교통)의 정규화 기준을 통일해야 가중합이 의미 있어짐
- **소음 지표**: 구·군 단위 공개 데이터가 없어 1차 버전에서 제외 (향후 확장 과제)
